## API de login y OTP

| Operación | Respuesta esperada |
|---|---|
| `POST /api/v1/auth/login` | `200` con sesión para correo verificado; `202` con `emailVerificationRequired=true` y `verification` para una cuenta válida aún no verificada. La respuesta pendiente no emite access token y limpia la cookie refresh previa. Incluye `Cache-Control: no-store`. |
| `POST /api/v1/mobile/auth/login` | `200` con sesión móvil para correo verificado; `202` con el desafío OTP cuando debe verificarse. La respuesta pendiente no contiene tokens de sesión ni crea cookie web. Incluye `Cache-Control: no-store`. |
| `POST /api/v1/auth/otp/verify` | Recibe `verificationToken` y `code`; al verificar, consume el código y crea la sesión web con cookie HttpOnly. |
| `POST /api/v1/mobile/auth/otp/verify` | Recibe el mismo contrato; al verificar, crea sesión móvil JSON sin cookie web. |
| `POST /api/v1/auth/otp/resend` / `POST /api/v1/mobile/auth/otp/resend` | Recibe `verificationToken`; un reenvío válido sustituye el código anterior y devuelve un desafío renovado. |

Errores de OTP usan códigos estables: `EMAIL_OTP_INVALID`, `EMAIL_OTP_EXPIRED`, `EMAIL_OTP_LOCKED`, `EMAIL_OTP_RATE_LIMITED` y `EMAIL_DELIVERY_FAILED`. La entrega fallida se devuelve como `503` genérico, sin detalles del servidor SMTP.

## Reglas de OTP y almacenamiento

- Se genera un código numérico de seis dígitos con `SecureRandom`; vence a los cinco minutos y solo puede consumirse una vez.
- Se permiten tres envíos por usuario en cualquier ventana móvil de sesenta minutos, incluyendo el envío inicial. El conteo está ligado al usuario y sobrevive a un cambio de correo.
- Dos validaciones incorrectas consecutivas invalidan el código y bloquean la verificación durante treinta minutos. El reenvío no borra los intentos ni el bloqueo.
- Los códigos se persisten como HMAC-SHA-256 con separación de contexto; el token de verificación se persiste como hash SHA-256. No se guardan OTP ni tokens en claro.
- Un cambio de correo quita `email_verified_at` e invalida el desafío vigente sin reiniciar el límite de envíos. El backend no concede autoridades a una cuenta cuyo correo no esté verificado.
- La tabla nueva `email_otp_challenge` conserva intentos, bloqueo y las tres marcas de envío. `V13__email_verification_otp.sql` agrega además `app_user.email_verified_at`.

## Adaptador Gmail y credenciales

`OtpEmailSender` separa la lógica de OTP del transporte. `SmtpOtpEmailSender` implementa Gmail mediante `spring-boot-starter-mail`, `smtp.gmail.com:587`, autenticación habilitada y STARTTLS habilitado y obligatorio. Los tiempos máximos de conexión, lectura y escritura son 5000 ms. La configuración está en `backend/src/main/resources/application-local.properties`.

El perfil local acepta exclusivamente el remitente y el destinatario de prueba aprobados. Si el usuario SMTP configurado no coincide con el remitente aprobado, si falta una credencial o si el destinatario no coincide con la lista local, el envío se rechaza antes de llamar al transporte. Otros perfiles no habilitan entrega por defecto.

Las credenciales se suministran con `SPRING_MAIL_USERNAME` y `SPRING_MAIL_PASSWORD` únicamente en `backend/.local/ruta-fija-native.env`, archivo local privado; en la prueba se leyó solo mediante el importador para cargar variables al proceso, nunca se imprimió la contraseña y no se modificó el archivo. No escribir la contraseña de aplicación en el chat, argumentos de comandos o registros. Gmail requiere verificación en dos pasos para crear contraseñas de aplicación y puede no ofrecerlas bajo ciertos ajustes de cuenta; la elegibilidad sigue pendiente de comprobación en la cuenta.

## Contratos de cliente

- CRM conserva el desafío en memoria; no persiste OTP ni token de verificación. Muestra campo numérico de seis dígitos, vencimiento local, reenvío y retorno al login. Solo crea sesión y carga `/auth/me` después de verificar.
- Flutter sigue el mismo flujo y no escribe un refresh token en almacenamiento seguro hasta completar el OTP. La entrada admite seis dígitos y muestra el vencimiento; la validación física queda en L-08.
- Las pruebas automáticas reemplazan `OtpEmailSender` por un mock; ninguna prueba automática llama Gmail.

| Operación | Ruta | Comportamiento |
|---|---|---|
| Inscripción única | `POST /api/v1/auth/super-admin-recovery/enrollment` | Requiere sesión SUPER_ADMIN, reautenticación, cuenta activa y correo verificado. Acepta clave pública X.509 Ed25519; devuelve código de emergencia una sola vez. |
